# NIST's SSDF catalog copy

`src/nist_sp_800_218/schema/oscal-content/` holds two files: `NIST_SP800-218_ver1_catalog.json`, the catalog of SP 800-218 version 1.1 that NIST publishes in the Open Security Controls Assessment Language (OSCAL), and NIST's `LICENSE.md`. NOTICE says that both were retrieved from usnistgov/oscal-content at commit `f0de6d8d8c059d374f15e0ae07508d82e370fc1d`, the v1.6.0 release, and are identical to their counterparts there.[^notice] It also says that NIST's work is in the public domain within the United States, and that NIST dedicates it to the worldwide public domain under CC0 1.0.

## What the catalog holds

The catalog's metadata names its framework version `SP_800_218_1_1_0` and its publication status `Final`, and says that it was generated by NIST's Cybersecurity And Privacy Open Reference Datasets In OSCAL (CAPORDINO). It is written in OSCAL `v1.2.3`.[^nist_sp800-218_ver1_catalog.json] Its four groups are the practice groups. Each group's controls of class `practice` are the practices, and each practice's controls of class `task` are the tasks. A task's parts named `example` are its notional implementation examples, and its links with the relation `external_reference` point at the back matter's resources, the documents it maps to.

`tests/test_upstream.py` derives an `SsdfFramework` from the copy with the standard library's JSON parser, validates it, and holds it to the counts of the publication: 4 practice groups, 19 practices, 42 tasks, 198 implementation examples, 528 references and 29 reference documents.[^test_upstream.py] The catalog appends a moved task's former identifier to the task's statement, such as `.Formerly PW.3.1` at the end of `PO.1.3`, and the test moves it into `former_task_ids`.

## The pins

`scripts/check_upstream_release.py` pins the tag `v1.6.0`, the commit, and each file's git object hash: `26a309a600160ea4f937854c13f53c578c1c458b` for the catalog and `109af23dd24c2c465143aeab12ffebfffe2a4cd5` for the licence.[^check_upstream_release.py] The test checks the hashes offline, and the upstream watch checks them against the pinned commit every week. [Update the upstream pins](../playbooks/update-upstream-pins.md) says how to replace the copy.
